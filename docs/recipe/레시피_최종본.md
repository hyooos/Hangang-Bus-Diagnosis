## 레시피 개요

- 신규 도입된 대중교통 수단은 기존 수단보다 느리거나 배차가 길어 이용이 저조하고, 이것이 적자와 재정지원 논란으로 이어지는 경우가 많음
    - 사례인 한강버스는 2025년 매출 54억원 중 여객 운송수입이 2억원에 그쳤고[S3], 시의회에서는 대중교통인지 관광수단인지 정체성부터 정해야 한다는 지적이 나옴[S6]
    - 그런데 한강버스의 부담은 배 위가 아니라 **배 밖**에 있음. 마곡→잠실 체감 통행시간 265분 중 132분(50%), 뚝섬→잠실 120분 중 106분(88%)이 대기·환승·도보임
        
        ⇒ 배 속도를 올리는 것보다 **시간표를 고치는 것이 먼저**
        
- 그래서 이 레시피는 **"배차가 길고 차량이 한정된 노선에서, 공개 시간표만으로 대기가 왜 긴지 원인별로 나누고, 보유 차량 안에서 비용이 들지 않는 처방부터 순서를 정하는"** 절차를 제시함
    - **① 지표**: 기다림·환승·걷기를 합친 **체감 통행시간(TFI)**으로 얼마나 기다리는지 계산
    - **② 원인 분해**: 대기를 배차 길이, 불규칙성, 환승 엇갈림, 교차 정차, 접근성으로 나눠 **왜 기다리는지** 진단
    - **③ 처방 메뉴**: 원인에 맞는 처방을 **필요 선박 수 기준**으로 정렬(비용 없음 → 보유 선박 안 → 투자 필요 → 하지 말 것)
- 처방은 두 계열로 나뉨
    - **대기를 줄이는 처방**: 환승 동기화, 증편, 전편 정차
    - **빈 편을 채우는 처방**: 평일 낮 고령층 건강 코스, 주말 유아차 동반 가족 탑승 시범
- 결과적으로
    - 선박을 늘리지 않고 여의도 환승 출발시각만 맞춰도 마곡→잠실 체감 통행시간이 **236분 → 193분(−18%)**으로 줄고,
    - 보유 12척 안에서는 **예비선을 몇 척 남기느냐**에 따라 최선이 달라지며,
        - **✅ 예비선 2척(운항 10척)**
            - **30분 배차 + 동기화**가 최선 → 마곡→잠실 −26%, 뚝섬→잠실 −60%
        - **✅ 예비선 1척(운항 11척)**
            - 압구정·옥수까지 매번 서는 **30분 배차 + 전편 정차 + 동기화**가 최선 → 8개 선착장 전체 체감시간 116분 → 110분, 압구정·옥수 대기 절반
    - **격편 급행만 넣으면 오히려 5% 나빠진다**는 것을 사전에 확인할 수 있음
- 필수 입력은 **공개 시간표와 보유 차량 수뿐**임. 운영사가 가진 승하선 실적이 있으면 가중치로 넣어 정밀도를 높이고, 없으면 인접 지하철역 승하차로 대체함
- **시간표·정류장·인접역·보유 차량 수만 바꾸면 농어촌 버스, 수요응답형 셔틀, 신규 수상·순환 노선에 그대로 재사용할 수 있음**

### ① 지표: 얼마나 기다리나

#### 기대대기시간

- 시간표를 보지 않고 아무 때나 정류장에 온 승객이 평균적으로 기다리는 시간[R6]

$$
E[W] = \frac{\sum_i h_i^2}{2\sum_i h_i} = \frac{\bar h}{2}\,(1 + CV^2)
$$

- 배차가 일정하면 배차의 절반이지만, 들쭉날쭉하면 승객이 긴 배차 구간에 걸릴 확률이 높아 절반보다 길어짐 → `(1 + 변동계수²)`가 **불규칙성 벌점**
- 판단 기준: 미국 대중교통 서비스수준 지침(TCQSM)[R7]의 배차 등급
    - 기대대기 5분 미만(배차 10분 미만) → 시간표 없이 타는 수준
    - 15분 이상(배차 30분 이상) → 시간표에 맞춰야 하는 수준
    - 30분 이상(배차 60분 이상) → 최하 등급
- **✅ 수식을 풀어서 보면**
    - **평균배차 ÷ 2**: 배차가 완전히 일정할 때의 평균 대기 (60분마다 오면 평균 30분)
    - **(1 + 변동계수²)**: 배차가 들쭉날쭉해서 더 기다리게 되는 배수 = 불규칙성 벌점
    - **변동계수**: 배차 간격의 표준편차 ÷ 평균
    
    그래서 `불규칙성 벌점 = 실제 기대대기 ÷ (평균배차 ÷ 2)`로 계산함
    
    #### 왜 들쭉날쭉하면 더 기다리나
    
    평균 배차가 60분으로 같은 두 노선을 비교해보면,
    
    **A노선: 60분, 60분 간격**
    
    - 평균 대기 = 60 ÷ 2 = **30분**, 벌점 = **1.00**
    
    **B노선: 30분, 90분 간격 (평균은 똑같이 60분)**
    
    - 아무 때나 온 승객은 120분 중 90분 구간에 걸릴 확률이 3/4, 30분 구간에 걸릴 확률이 1/4
    - 90분 구간이면 평균 45분, 30분 구간이면 평균 15분 기다림
    - 평균 대기 = 3/4 × 45 + 1/4 × 15 = **37.5분**, 벌점 = 37.5 ÷ 30 = **1.25** (25% 더 기다림)
    
    핵심은 **긴 간격일수록 승객이 그 안에 걸릴 확률도 높다**는 점. 버스가 몰려 다니면 평균 배차는 같아도 더 오래 기다리는 것과 같은 원리
    
    #### 벌점 읽는 법
    
    | 벌점 | 의미 |
    | --- | --- |
    | 1.00 | 완전히 일정한 배차 |
    | 1.1 안팎 | 약간 불규칙. 추가 대기는 평균 대기의 10% 정도 |
    | 1.25 | 30분·90분이 번갈아 오는 수준 |
    | 1.5 이상 | 많이 불규칙. 몰려 오거나 큰 공백이 있음 |

#### 환승대기

- 환승 거점(한강버스는 여의도)에 도착한 뒤 **최소 환승 3분**이 지나고 처음 떠나는 연결편까지의 시간
- 기준선은 두 노선이 서로 무관하게 운항할 때의 기대값(연결 노선 배차의 절반, 60분 배차면 약 30분)
    
    ⇒ 이보다 커지면 시간표가 오히려 **엇갈려 있다**는 뜻
    
- **✅ 최소 환승 3분의 근거와 민감도** ⇒ 결론은 이 가정에 흔들리지 않음
    - 3분은 배에서 내려 같은 선착장에서 다른 배에 타는 데 필요한 최소 시간으로 둔 **레시피 가정**(실제 승하선 소요시간 자료는 비공개)
    - 그래서 2분/3분/5분으로 바꿔 계산해봄
    
    min_transfer_sensitivity.py
    
    | 최소 환승시간 | 현행 환승대기 마곡→잠실 | 현행 환승대기 잠실→마곡 | 현행 편성 + 동기화 | 15분 배차 + 동기화 |
    | --- | --- | --- | --- | --- |
    | 2분 | 평균 26분(12~37분) | 평균 39분(5~88분) | 191분(−19%) | 159분(−32%) |
    | **3분(기준)** | 평균 26분(12~37분) | 평균 39분(5~88분) | 193분(−18%) | 161분(−32%) |
    | 5분 | 평균 26분(12~37분) | 평균 39분(5~88분) | 197분(−16%) | 165분(−30%) |
    - **현행 환승대기는 2~5분 어느 값에서도 똑같음** → 현재 가장 빠듯한 환승도 5분 여유가 있어서 가정 때문에 놓치는 편이 없음
    - 동기화는 "도착 + 최소 환승시간"에 출발을 맞추므로 가정이 커질수록 효과가 조금 줄지만(−19% → −16%), **처방 순위는 세 값 모두 같음**

#### 체감 통행시간(TFI, 환승마찰지수)

- 모든 부담을 "앉아서 타고 가는 시간 몇 분과 같은가"로 환산한 값(분)

$$
TFI = t_{ride} + 1.8\,(w_{first} + w_{transfer}) + 10\,n_{transfer} + c_{walk}
$$

- 국내 연구의 가중치를 차용함
    - 기다리는 1분은 타고 가는 1분보다 1.7~2.0배 힘들고[R3], 갈아타기 한 번은 10~15분만큼의 부담[R4]
    - 외부 보행은 100m당 2분[R5], 지하철 환승 통로 도보는 1분 = 1.6분
- 판단 기준: 같은 출발역·도착역의 **지하철 TFI와 비교**
    - 비율 1.0 이하 경쟁 가능 / 1.0~1.5 여가·쾌적성 수요권 / 1.5 이상 통근 대체 어려움
    - 비율보다 **배 밖 부담(TFI − 차내시간)의 분 차이**를 지하철과 비교하는 게 더 명확함 (지하철도 환승 벌점 때문에 비율로는 차이가 잘 안 드러남)
- **✅ 1분 = 1.6분은 어디서 나왔나**
    - 외부 보행 100m당 2분(김황배·권영종 2010[R5])에서 역산한 값
    - 보통 걸음을 분당 약 80m로 보면 100m는 실제 1.25분 → 이걸 2분으로 느낀다는 건 1.6배라는 뜻
    - 지하철 환승 데이터[D5]는 거리가 아니라 소요시간(분)이라 같은 비율을 적용함

### ② 원인 분해: 왜 기다리나

- 대기를 다섯 가지 원인으로 나누고, 원인마다 맞는 처방을 짝지움 ← **이 표가 이 레시피의 중심**

| 진단 신호 | 원인 | 처방 | 처방 계열 |
| --- | --- | --- | --- |
| 불규칙성 벌점 1.25 이상 | 출발 간격이 들쭉날쭉 | 출발 간격 균등화 | 대기 줄이기 |
| 환승대기 ≥ 연결 노선 배차의 절반 | 노선 간 시간표 엇갈림 | 환승 거점 출발 동기화 | 대기 줄이기 |
| 같은 노선·방향에서 정차 편수가 최대 편수의 절반 이하(배차 약 2배) | 교차(격편) 정차 | 전편 정차 검토 | 대기 줄이기 |
| 평균 배차 30분 이상(기대대기 15분 이상) | 운행 횟수 부족 | 보유 차량 안 증편 | 대기 줄이기 |
| 도보 부담이 크고 이용층 조건에서 더 커짐 | 접근성 | 접근 경로 안내·탑승 규정 개선 | 대기 줄이기 |
| 특정 시간대 탑승률 낮음 + 주변에 잠재 이용층 존재 | 빈 좌석 | 이용층 연결 코스·시범 | 빈 편 채우기 |
- **✅ 원인을 나눠야 처방의 크기를 미리 알 수 있음** (잠실 여의도행 예시)
    
    잠실(여의도행)의 기대대기 31분을 둘로 나누면,
    
    - 배차가 긴 탓: 27.8분
    - 들쭉날쭉한 탓: 3.2분
    
    그래서 처방의 효과도 크기가 달라짐
    
    - **간격만 고르게 맞추면**: 31분 → 27.8분, 약 3분 줄어듦
    - **배차를 절반(28분)으로 줄이면**: 약 14분이 되어 17분 가까이 줄어듦
    
    ⇒ 지금 한강버스는 "배가 고르지 않게 와서"가 아니라 **"배가 드물게 와서"** 기다리는 것. 간격 정리보다 배차 단축이나 환승 동기화가 효과가 큼
    
- **이용층 재계산**: 같은 TFI를 이용층 조건으로 다시 계산해 접근성 신호를 이용층별로 봄
    - 유아차 동반 가족: 계단 구간을 엘리베이터·경사로 우회로 바꿈(인접역 지상 출구 엘리베이터[D6] + 현장 확인)
    - 고령층: 보행속도를 1.2m/s → 1.0m/s로 낮춤(가정, 한계 참조)

### ③ 처방 메뉴: 무엇부터 고치나

- 원인 분해에서 나온 처방 후보들을 실제 시간표로 만들어보고, 보유 차량 안에서 체감대기가 가장 짧은 안을 찾음

|  | 내용 |
| --- | --- |
| 결정변수 | 노선별 배차 간격 h, 환승 거점 출발 오프셋 o, 정차 패턴 |
| 목적함수 | 정류장·시간대 가중치 w로 합한 체감대기 최소화 |
| 제약 | 보유 차량 수(한강버스 12척), 운항 시간대 유지(11~21시), 최소 환승 3분 |
| 풀이 | 후보가 많지 않아 배차 × 오프셋 격자 전수탐색 |

$$
\min_{h,\,o}\; \sum_{s,t} w_{s,t}\, \mathrm{Wait}_{s,t}(h,o) \quad \text{s.t.}\quad \sum_r \left\lceil \frac{T_r}{h_r} \right\rceil \le N
$$

- T_r은 노선의 왕복 운항시간(서측 97분, 동측 180분), N은 보유 차량 수
- 기대대기 식 안에 배를 놓치면 다음 배까지 기다리는 효과가 이미 들어 있어서, 놓침 벌점은 따로 더하지 않음(이중으로 세지 않기 위해)
- **가중치 w**
    - 운영사 승하선 실적이 있으면 → 정류장·시간대별 승차 비율
    - 없으면 → 인접역 휴일 쏠림 지수(HCI)로 정류장 간 비중
    - 균등·HCI 기준으로 바꿔도 처방 순위가 유지되는지 확인함(62개 후보 순위 상관 0.998, 상위 6개 동일). 실적이 확보되면 같은 방식으로 다시 확인
- **처방 정렬**: 결과는 필요 차량 수 기준 네 단계로 정렬
    - 비용 없음 → 보유 차량 안 → 투자 필요 → **하지 말 것(역효과)**

#### 수요 반응

- 처방 간 크기를 비교하기 위해 고정탄력성 수요함수[R2]를 씀 ("체감 통행시간이 1% 늘면 이용이 ε% 변한다")

$$
\frac{D_{new}}{D_{base}} = \left(\frac{TFI_{new}}{TFI_{base}}\right)^{\varepsilon}
$$

- 변화가 커도 음수 수요 같은 비현실적 값이 나오지 않아 영국 교통연구소 수요 지침의 표준 형태
- 해외 연구값이라 ε를 −0.3/−0.5/−0.7로 바꿔 범위로 제시하고, **이용객 수 예측이 아니라 처방 간 크기 비교**에만 씀
- 판단 기준: 보수값(ε=−0.3)에서도 +10% 이상이면 "효과 확실", −0.5에서만 +10% 이상이면 "시범 후 확인", 세 값 모두 ±5% 이내면 "미미", 음수면 "역효과"

### 데이터 변수 가이드라인

- 타겟변수 ① **체감 통행시간(TFI, 분)** `얼마나 불리한가`
    
    → 배 위 시간만 보면 동기화·배차 개선 효과가 보이지 않으므로 대기·환승·도보를 한 단위(분)로 합친 지표가 필요함. 그래야 지하철보다 얼마나 불리한지를 공정하게 비교할 수 있음
    
    - 데이터셋 ①로 기대대기와 환승대기를 구하고 차내시간·도보와 가중합
    - 데이터셋 ③으로 같은 출발역·도착역의 지하철 TFI를 같은 식으로 구해 비교
- 타겟변수 ② **휴일 쏠림 지수(HCI)** `어느 정류장부터 처방할까`
    
    → 정류장별 승하선 실적이 없을 때 인접역 하차를 대리지표로 씀. 휴일 하차 인원을 그대로 쓰면 큰 역(압구정, 잠실새내)이 무조건 높게 나오므로 "그 역의 평일 대비 휴일 비율"로 규모 효과를 빼고, 서울 전체 비율로 한 번 더 나눠 계절·연휴 효과를 뺌
    
    - 인접역의 (휴일 평균 하차 ÷ 평일 평균 하차)를 서울 전체의 같은 값(2026.1~8 기준 0.647)으로 나눔
    - 1보다 크면 서울 평균보다 휴일에 사람이 더 모이는 역
- 타겟변수 ③ **평일 낮 고령층 집중도** `빈 편을 누구로 채울까`
    
    → 평일 낮(10~17시)은 한강버스 좌석이 비는 시간이자 고령층이 움직이는 시간이라 둘이 겹치는 곳을 찾기 위한 지표. 인원 대신 비중을 써서 역 규모 효과를 뺌
    
    - 데이터셋 ④에서 인접역의 평일 10~17시 노인 하차 ÷ 평일 전일 노인 하차를 관할역 전체 평균으로 나눔
- 타겟변수 ④ **건강 코스 걸음 수** `건강 처방이 의미가 있나`
    
    → 목표가 하루 6,000~8,000보[R1]·손목닥터9988 8,000보[S7]이므로 코스가 목표를 채우는지 걸음 수로 바로 확인
    
    - (출발 거점 → 정류장) + (도착 정류장 → 역) 거리를 보폭 0.65m(0.6/0.7m 민감도)로 나누고, 8,000보까지 모자란 거리를 도착 공원 산책 구간으로 배정

### 1. 시간표 정형화

`build_timetable.py`

- 운영사 누리집의 시간표는 **이미지**로 게시되어 있어서 위 컬럼 구조의 표로 옮겨야 함
    - 직접 옮기거나, 멀티모달 AI로 이미지를 표로 변환한 뒤 사람이 편수·첫 출발·막 출발 시각을 원본과 대조하는 방식으로 할 수 있음
    - 어느 쪽이든 7단계에서 손계산 값과 다시 대조함
- 시간표에는 "각 선착장 출발 시간 기준"으로 적혀 있고, 도착 시각은 양 끝 종점만 나와 있음
    
    → 환승대기를 계산하려면 환승 거점 도착 시각이 필요해서 **직전 선착장 출발 + 공식 구간시간**으로 추정함 (예: 망원 11:42 + 26분 = 여의도 12:08). 실제 접안에 따라 1~3분 차이가 날 수 있음
    

```python
import numpy as np, pandas as pd
tt = pd.read_csv('data/hangang_timetable.csv', dtype=str, keep_default_na=False)
m = lambda s: int(s[:2]) * 60 + int(s[3:]) if s else np.nan
tt['DEP'] = tt.DEP_HM.map(m); tt['ARR'] = tt.ARR_HM.map(m)
```

### 2. 지표 산출

`timetable_metrics.py`

- 정류장·방향별 편수, 평균 배차, 기대대기, 불규칙성 벌점, 환승대기를 계산
    
    → 첫 배가 11:00(잠실)·11:20(마곡)이라 출근 시간대 운항이 없음도 여기서 확인됨
    

```python
def expected_wait(dep):
    h = np.diff(np.sort(dep)); return (h ** 2).sum() / (2 * h.sum())

def transfer_waits(arr, dep, min_tr=3):
    dep = np.sort(dep); idx = np.searchsorted(dep, arr + min_tr); ok = idx < len(dep)
    return dep[idx[ok]] - arr[ok]
```

- ② 원인 분해 표의 진단 신호를 정류장마다 판정함

### 5-A. 대기 줄이기: 후보 시간표 탐색

`scenarios.py`

- 배차(60/30/15분), 여의도 동기화, 격편 급행을 조합해 하루 시간표를 만들고, 11:00~18:40에 1분 간격으로 도착하는 가상 승객이 TFI가 가장 작은 배 조합을 고른다고 보고 평균을 냄
    - 11:00은 운항 시작, 18:40은 마곡 막 배 출발. 모든 시나리오를 같은 승객 집단으로 비교하기 위해 통일함
- 동기화하지 않는 시나리오는 두 노선 출발 시각차를 0~(배차−1)분으로 바꿔 평균
- 급행은 서울시 원계획(일반 75분·급행 54분, 정차 4곳 생략)에서 역산한 정차 1회당 5.25분 절감 적용
- 필요 선박 = 올림(왕복 운항시간 ÷ 배차), 서측 97분·동측 180분
- **격자 전수탐색** (`optimize_timetable.py`): 노선별 배차(60/45/40/30/25/20분) × 여의도 출발 오프셋(0~배차−1분) × 정차 패턴(교차/전편)을 12척 이내에서 모두 시험(62개 후보). 목적함수는 8개 선착장에서 노선 끝(잠실 방향은 잠실, 마곡 방향은 마곡)까지의 TFI를 정류장 가중치(균등/HCI)로 합한 값
    - 전편 정차는 압구정·옥수를 매번 들러 여의도→잠실이 85분 → 92분, 동측 왕복이 180분 → 194분으로 늘어남

```python
def best(t, legs, w=1.8, pen=10, min_tr=3):      # 체감비용 최소 배 조합
    out = None
    for d1, a1 in legs[0]:
        if d1 < t: continue
        for d2, a2 in legs[1]:
            if d2 < a1 + min_tr: continue
            c = w * ((d1 - t) + (d2 - a1)) + (a1 - d1) + (a2 - d2) + pen
            out = c if out is None else min(out, c)
    return out

demand_change = lambda new, base, eps: (new / base) ** eps - 1
ships = lambda hw: -(-97 // hw) - (-180 // hw)    # 서측 + 동측 필요 선박
```

### 5-B. 빈 편 채우기: 이용층 코스 설계

`kyungrodang_courses.py`

1. **빈 편 찾기**: 승하선 실적으로 평일 낮 탑승률이 낮은 편을 고름. 실적이 없으면 통근 시간대(07~10시, 17~20시) 밖의 편으로 대체

3. **걸음 수 계산**: 거점 → 정류장 + 도착 정류장 → 역 거리를 보폭으로 나눔

- 가족 유아차 탑승 시범은 가족 수요 점수가 높고 역에서 가까운 정류장(8개 정류장 중앙값 기준 사분면)을 대상으로 고름

- **보유 12척 안 최선**: 정비·고장에 대비해 남기는 **예비선 수**에 따라 달라짐 (실제 예비선 기준은 비공개라, 운영사가 자기 기준으로 고르도록 두 안을 함께 제시)
    - **✅ 예비선 2척(운항 10척): 30분 배차 + 동기화**
        - 마곡→잠실 236분 → 175분(−26%), 뚝섬→잠실 100분 → 40분(−60%)
        - 장거리 구간만 보면 가장 좋은 보유 선박 안
        - 다만 압구정·옥수는 교차 정차가 남아 대기가 여전히 50분 안팎
    - **✅ 예비선 1척(운항 11척): 30분 배차 + 전편 정차 + 동기화**
        - 압구정·옥수를 매번 들러 두 선착장의 배차가 약 100분 → 30분으로 줄어듦
        - 대신 여의도→잠실 배 위 시간이 7분 늘어 마곡→잠실은 182분(−23%)으로 10척 안(175분)보다 조금 불리함
        - 8개 선착장 전체 가중 체감시간은 116분 → 110분으로 더 짧음 (12척 제약 격자 전수탐색 62개 후보 중 2위, 10척 안은 8위)
        - 원인 분해의 "교차 정차 → 전편 정차 검토" 처방이 실제 시간표에서 효과를 내는 안
    - (참고) 예비선 0척(12척 전부 운항)이면 25분 배차 + 전편 정차 + 동기화가 1위(가중 체감시간 105분)지만, 고장 시 바로 결항이 생겨 권장하지 않음
- **15분 배차**가 가장 효과적이지만 18~19척이 필요해 현재 12척으로는 불가능함 → 서울시의 2030년 18척 계획[S1]과 연결되는 투자 단계
- **급행 단독은 역효과**: 정차를 건너뛰는 만큼 생활권 이동이 희생되어 뚝섬→잠실이 20% 나빠짐. 15분 배차에 급행을 더해도 장거리는 8분 줄지만 생활권 개선 폭은 −73% → −60%로 줄어듦 → 급행은 마지막 순서
- 대기 가중치·환승 벌점 6개 조합, 최소 환승시간 2~5분 모두에서 처방 순위가 같았음 → **"동기화 우선"이라는 결론은 가정에 흔들리지 않음**

## 예상성과

- **운영 효율화**: 선박 추가 없이 출발 시각만 조정해 장거리 체감 통행시간을 약 18% 줄이고, 보유 선박 안에서 예비선 수에 맞춘 안(예비선 2척: 30분 배차 + 동기화로 장거리 26%·생활권 60% 단축 / 예비선 1척: 전편 정차를 더해 8개 선착장 전체 체감시간 추가 단축)을 제시해 **증차 전에 할 일의 순서**를 정할 수 있음
- **잘못된 투자 방지**: 격편 급행 단독은 역효과(장거리 +5%, 생활권 +20%)임을 사전에 보여, 효과 없는 처방에 예산이 쓰이는 것을 막을 수 있음
- **정체성 논의의 근거**: 지하철 대비 체감시간 비율로 "통근 대체는 어렵고(1.6~4.9배) 생활권 구간만 배차 개선 시 여가 수요권(1.3배)에 들어온다"는 점을 수치로 제시해, 대중교통 대 관광수단 논의에 이용층별 근거를 제공할 수 있음
- **빈 좌석의 수요화**: 평일 낮 빈 좌석을 고령층 걷기 수요와, 주말 좌석을 휴일 가족 수요와 연결해 운송수입 외 선착장 주변 상권으로 효과를 넓힐 수 있음(여의도 선착장 반경 500m 생활인구 +20.9%, 음식점 카드매출 +15.5%[S5])
- **재사용성**: 필수 입력이 공개 시간표와 보유 차량 수뿐이라, 승차 실적이 쌓이기 전인 신규 노선 도입 초기부터 쓸 수 있음

## 분석결과 활용방안

- **운영사**: 처방 메뉴판의 1순위(환승 동기화)를 다음 시간표 개편에 반영하고, 개편 전후 승하선 실적을 비교해 효과를 확인함. 실적이 쌓이면 가중치를 실적 기반으로 바꿔 같은 절차를 다시 돌림

- **다른 운영 주체로의 확산**: 아래 치환표대로 입력만 바꿔 넣으면 됨

## 부록 C. 확장 분석

- **✅ C-1. 계단 없는 보행 경로(OSM)**
    - OSM 보행망에서 `highway=steps`(계단) 구간을 지우고 역 엘리베이터 출구에서 선착장까지 최단거리(다익스트라)를 다시 구하면, 계단 없이 돌아가는 길이 자동으로 선택되어 유아차 추가 거리를 얻을 수 있음
    - 다만 공식 도보거리와 ±30% 이내로 맞은 곳은 4곳(마곡 +10%, 망원 +14%, 압구정 0%, 서울숲 −24%)뿐이고, 나머지 4곳(옥수 +55%, 잠실 +167%, 여의도 +187%, 뚝섬 +568%)은 한강공원 나들목(올림픽대로·강변북로 밑 통로) 연결이 OSM에 빠져 있었음
        
        ⇒ 그래서 본문 절차에서는 공식 도보거리 + 현장 확인을 기본으로 했음
        
    
    ```python
    import osmnx as ox, networkx as nx
    G = ox.graph_from_point(pier_latlon, dist=2100, network_type='walk')
    G.remove_edges_from([(u, v, k) for u, v, k, d in G.edges(keys=True, data=True)
                         if 'steps' in (d['highway'] if isinstance(d['highway'], list) else [d['highway']])])
    dist = nx.single_source_dijkstra_path_length(G, ox.distance.nearest_nodes(G, lon, lat), weight='length')
    ```
