## 레시피 개요

- 신규 도입된 대중교통 수단은 기존 수단보다 느리거나 배차가 길어 이용률이 낮고, 이것이 적자와 재정지원 논란으로 이어지는 경우가 많음. 이 레시피는 **"속도로는 기존 수단을 이길 수 없는 신규 교통수단이 누구에게, 어디서, 무엇을 고치면 쓰일 수 있는가"**를 공개 데이터만으로 진단하는 절차를 제시함
- 사례인 한강버스는 수심 제약으로 약 17km/h 이상 내기 어려워 통근 속도로는 지하철과 경쟁하기 어려움. 2025년 매출 54억원 중 여객 운송수입은 2억원에 그쳤고[S3], 시의회에서는 대중교통인지 관광수단인지 정체성부터 정해야 한다는 지적이 나옴[S6]. 반면 2026년 3월 이후 주말 탑승객 비중은 약 51%이고[S4], 선착장 인접역에는 휴일마다 한강을 찾는 수요가 이미 모이고 있음
- 운항 시간표와 교통카드 데이터로 대기·환승·도보 부담을 **체감 통행시간(환승마찰지수, TFI)**으로 환산하고, 유아차 동반 가족과 고령층 조건으로 다시 계산해 선착장별 **수요 신호 × 접근성**을 비교함. 고령층은 도보 거리를 걸음 수로 바꿔 건강 목표(하루 6,000~8,000보) 달성 여부도 평가함
- 결과적으로 선박 추가 없이 가능한 처방(여의도 환승 동기화, 유아차 동반 시범, 건강 코스)과 투자가 필요한 처방(배차 단축, 급행)의 우선순위를 정하고, 주말 요금 인상 같은 정책 변화가 이용층별로 미치는 영향을 사전에 추정할 수 있음. 시간표·선착장·인접역만 바꾸면 다른 신규 노선(수상교통, 경전철, 신규 버스노선 등)에 그대로 재사용할 수 있음

## 분석모델 및 알고리즘

| 분석모델 | 알고리즘 |
| --- | --- |
| 진단 분석(일반화비용 기반 시나리오 시뮬레이션) | 환승마찰지수(TFI) + 탄력성 기반 수요 반응 모형 |

> 포털 분석모델이 선택지라면 "최적화 분석" 또는 "시뮬레이션"을 고르고, 아래 설명란에 세부 기법을 적음.

- **세 지표의 관계**: 시간표 → ① 기대대기시간·환승대기(얼마나 기다리나) → ② 환승마찰지수 TFI(기다림·환승·걷기를 합친 체감 통행시간) → ③ 수요 반응(TFI가 바뀌면 이용이 얼마나 바뀌나)의 한 줄 사슬임. ①은 TFI의 재료이고, ③은 TFI의 변화를 이용 변화로 번역하는 단계임
- **기대대기시간**은 시간표를 보지 않고 아무 때나 선착장에 온 승객이 평균적으로 기다리는 시간으로, `Σ(배차간격²) ÷ (2 × Σ배차간격)`으로 계산함. 배차가 일정하면 배차의 절반이지만, 불규칙하면 승객이 긴 배차 구간에 걸릴 확률이 더 높아 절반보다 길어짐(무작위 도착 대기 모형[R6]). 판단 기준은 미국 대중교통 서비스수준 지침(TCQSM)[R7]의 배차 등급으로, 기대대기 5분 미만(배차 10분 미만)이면 시간표 없이 타는 수준, 15분 이상(배차 30분 이상)이면 시간표에 맞춰야 하는 수준, 30분 이상(배차 60분 이상)이면 최하 등급으로 봄. 현재 한강버스는 26~53분으로 최하~차하 등급임
- **여의도 환승대기**는 여의도 도착 후 최소 환승 3분이 지난 첫 출발편까지의 시간임. 기준선은 두 가지로, 동기화된 이상값은 약 3~5분, 두 노선이 서로 무관하게 운항할 때 기대값은 연결 노선 배차의 절반(60분 배차면 약 30분)임. 이 값보다 크면 시간표가 오히려 어긋나 있다는 뜻으로, 현재 마곡→잠실 26분은 "무조정" 수준, 잠실→마곡 39분은 무조정보다도 나쁜 수준임
- **환승마찰지수(TFI)**는 `배 위 시간 + 1.8×(첫 대기 + 환승대기) + 10×환승횟수 + 도보부담`으로, 모든 부담을 "배 위에 앉아 있는 시간 몇 분과 같은가"로 환산한 체감 통행시간(분)임. 기다리는 1분은 타고 가는 1분보다 1.7~2.0배 힘들게 느껴지고[R3], 갈아타기 한 번은 10~15분만큼의 부담이라는[R4] 국내 연구 가중치를 씀. 판단 기준은 ① 같은 출발·도착의 지하철 TFI 대비 비율(1.0 이하면 경쟁 가능, 1.5 이상이면 통근 대체 어려움)과 ② 마찰 비중 `(TFI − 배 위 시간) ÷ TFI`(30% 이상이면 속도보다 시간표·환승 개선 효과가 더 큼)임. 현재 마곡→잠실은 236분 중 103분(44%), 뚝섬→잠실은 88분 중 74분(84%)이 배 밖의 부담임. 유아차·고령층 TFI는 계단 구간을 엘리베이터·경사로 우회 경로로 바꾸고 고령층은 보행속도를 낮춰 다시 계산함
- **수요 반응**은 `새 수요 ÷ 현재 수요 = (새 TFI ÷ 현재 TFI)^ε`로, "체감 통행시간이 1% 늘면 이용이 ε% 변한다"는 고정탄력성 수요함수임. 변화가 클 때도 음수 수요 같은 비현실적 값이 나오지 않아 영국 교통연구소 수요 지침[R2]에서 표준으로 쓰는 형태임. 해외 연구값이라 ε를 −0.3/−0.5/−0.7로 바꿔 범위로 제시하고, 판단 기준은 **보수값(ε=−0.3)으로도 +10% 이상**이면 "효과 확실", 세 값 사이에서 부호가 바뀌면 "불확실"로 봄. 요금에 적용할 때는 |ε| < 1이면 요금을 올려도 운임수입은 늘지만 승객은 줄어든다는 뜻으로 해석함

**데이터 변수 가이드라인**

- 타겟변수 ① **이용층별 체감 통행시간(TFI, 분)**: 시간표 전처리로 선착장·방향별 기대대기시간과 여의도 환승대기시간을 구하고, 배 위 시간·도보시간과 가중합해 산출. 일반/유아차/고령층 세 조건으로 각각 계산
- 타겟변수 ② **휴일 쏠림 지수(HCI)**: 데이터셋 ②에서 선착장 인접역의 (휴일 평균 하차 ÷ 평일 평균 하차)를 서울 전체의 같은 값으로 나눠 도출. 1보다 크면 서울 평균보다 휴일에 사람이 더 모이는 역
- 타겟변수 ③ **평일 낮 고령층 집중도**: 데이터셋 ③에서 인접역의 평일 10~17시 노인 하차 ÷ 평일 전일 노인 하차로 도출
- 타겟변수 ④ **건강 코스 걸음 수**: 경로당 → 선착장 → 도착 공원 산책 → 복귀의 계단 없는 경로 거리를 보폭(0.65m, 0.6~0.7m 민감도)으로 나눠 도출

```python
    hw = d.get('highway')
    return 'steps' in (hw if isinstance(hw, list) else [hw])

    o = ox.distance.nearest_nodes(G, o_latlon[1], o_latlon[0])
    d = ox.distance.nearest_nodes(G, d_latlon[1], d_latlon[0])
    try:
        return nx.shortest_path_length(G, o, d, weight='length')
    except nx.NetworkXNoPath:
        return np.nan
```

**② 이용층별 TFI**: 도보는 일반 경로(일반) / 계단 없는 경로(유아차·고령층). 고령층 보행속도는 일반(1.2m/s) 대비 1.0m/s로 가정

```python
W_WAIT, PEN_TR, WALK_PER_100M = 1.8, 10, 2.0
SPEED_RATIO = {'일반': 1.0, '유아차': 1.0, '고령층': 1.2 / 1.0}

def tfi(ivt, wait1, wait_tr, n_tr, walk_m, group='일반'):
    walk = WALK_PER_100M * walk_m / 100 * SPEED_RATIO[group]
    return ivt + W_WAIT * (wait1 + wait_tr) + PEN_TR * n_tr + walk
```

### 5. 시나리오 시뮬레이션

- 배차(60/30/15분), 첫 배 시각, 여의도 동기화, 격편 급행을 조합해 하루 시간표를 다시 만들고, 1분 간격 가상 승객의 평균 첫 대기·환승대기·배 위 시간·TFI를 계산함
- 급행은 서울시 원계획(일반 75분·급행 54분, 정차 4곳 생략)에서 역산한 정차 1회당 5.25분 절감을 적용해 여의도→잠실 85분을 69분으로 가정함
- 필요 선박은 `올림(왕복 운항시간 ÷ 배차)`이며 서측 왕복 97분, 동측 왕복 180분(회차 4분 포함)을 사용함. 정비·예비선은 별도

```python
T_W, T_E, T_E_EXP, T_TTUK = 48, 85, 69, 14   # 마곡→여의도, 여의도→잠실(일반/급행), 뚝섬→잠실

def earliest_arrival(t, legs, i=0, min_tr=3):
    """legs: 구간별 [(출발, 도착), ...]. 최종 도착이 가장 빠른 조합을 고름"""
    if i == len(legs):
        return t, []
    ready = t if i == 0 else t + min_tr
    best_fin, best_path = np.inf, None
    for dep, arr in sorted(legs[i]):
        if dep < ready:
            continue
        if dep >= best_fin:
            break
        fin, path = earliest_arrival(arr, legs, i + 1, min_tr)
        if path is not None and fin < best_fin:
            best_fin, best_path = fin, [(dep, arr)] + path
    return best_fin, best_path

def evaluate(legs, t0, t1):
    rows = []
    for t in range(t0, t1):
        _, p = earliest_arrival(t, legs)
        if p is None:
            continue
        w1 = p[0][0] - t
        wtr = sum(p[k + 1][0] - p[k][1] for k in range(len(p) - 1))
        ivt = sum(a - d for d, a in p)
        rows.append((w1, wtr, ivt, ivt + 1.8 * (w1 + wtr) + 10 * (len(p) - 1)))
    return pd.DataFrame(rows, columns=['첫대기', '환승대기', '배위', 'TFI']).mean().round(0)

FIRST_E_YD = None   # 현행 시간표의 '여의도 출발 잠실행' 첫 배 시각(분). 3-①에서 확인해 입력 (잠실 첫 배 11:00과 다름)

def scenario(hw, first_w=11*60 + 20, first_e=FIRST_E_YD, last=20*60, sync=False, express=False):
    west = [(d, d + T_W) for d in range(first_w, last + 1, hw)]
    if not sync and first_e is None:
        raise ValueError('동기화하지 않는 시나리오는 여의도 잠실행 첫 출발(first_e)이 필요함')
    e_start = first_w + T_W + 3 if sync else first_e
    east = []
    for i, d in enumerate(range(e_start, last + 1, hw)):
        exp = express and i % 2 == 1
        east.append((d, d + (T_E_EXP if exp else T_E), exp))
    legs_mz = [west, [(d, a) for d, a, _ in east]]
    legs_tj = [[(d + T_E - T_TTUK, d + T_E) for d, a, exp in east if not exp]]   # 급행은 뚝섬 미정차
    ships = math.ceil(97 / hw) + math.ceil(180 / hw)
    return legs_mz, legs_tj, ships

def demand_change(new, base, eps):
    return (new / base) ** eps - 1

# 현행은 실제 시간표(3-①)로 legs를 만들고, 아래 시나리오와 비교
for name, kw in {'60분+동기화': dict(hw=60, sync=True), '60분+급행': dict(hw=60, express=True),
                 '15분': dict(hw=15), '07시+30분+동기화': dict(hw=30, first_w=7*60, sync=True)}.items():
    mz, tj, ships = scenario(**kw)
    r = evaluate(mz, mz[0][0][0], 19 * 60)
    print(name, r.to_dict(), '선박', ships,
          {e: f'{demand_change(r.TFI, 236, e):+.0%}' for e in (-0.3, -0.5, -0.7)})
```

### 6. 검증 및 민감도 분석

- **순위 안정성**: 같은 구간 안에서는 ε가 모든 시나리오에 똑같이 곱해지므로 ε는 효과의 **크기**만 바꾸고 순위는 바꾸지 않음. 순위를 바꿀 수 있는 것은 가중치이므로(시나리오마다 대기·환승·배 위 시간 구성이 다름) 대기 가중치 1.7/1.8/2.0, 환승 벌점 10/15분 조합에서 처방 순위(동기화 > 급행 단독 등)가 유지되는지 확인함. 순위가 바뀌는 처방은 "조건부 권고"로 표시
- **시간표 추정 검증**: 추정한 여의도 도착시각을 현장 관측 또는 운영사 운항기록과 비교해 오차(분)를 기록하고, 오차가 크면 구간시간을 보정함
- **수요 신호 검증**: HCI를 2025년 같은 기간(1~8월) 데이터로 다시 계산해 선착장 순위가 유지되는지 확인하고, 월별로 계산해 봄꽃·여름 시즌 편차를 확인함
- **인접역 매핑 검증**: 선착장별 2순위 인접역(예: 여의도 → 여의도역, 잠실 → 종합운동장)으로 바꿔 HCI 순위 변화를 확인함

- 격편 급행만 넣으면 마곡→잠실은 오히려 7% 늘고, 뚝섬 같은 중간 선착장은 정차편이 절반이 되어 20% 나빠짐. 15분 배차에서도 급행을 더하면 장거리는 8분 줄지만 뚝섬→잠실 개선 폭이 −73% → −60%로 줄어듦 → 급행은 생활권 이동을 희생하는 처방
- 15분 배차가 가장 효과적이지만 18~19척이 필요해 현재 12척으로는 불가능함. 보유 선박 안에서는 30분 배차 + 동기화(10척)가 최선
- 현재 뚝섬→잠실 100분은 잠실행 배가 13:49에야 뚝섬을 지나 오전 승객이 오래 기다리기 때문임. 첫 배 공백만 없애도 생활권 이동이 크게 좋아짐
- 역→선착장 공식 도보거리를 더하면 마곡(양천향교 720m)→잠실(잠실새내 770m)은 266분이 되고 그중 50%가 배 밖의 부담임. 어떤 시간표 처방으로도 장거리 통근 대체는 어려워, 이용층을 가족·고령층으로 넓혀야 하는 근거가 됨
- **검증**: 대기 가중치(1.7/1.8/2.0) × 환승 벌점(10/15분) 6개 조합 모두에서 처방 순위가 같음(`results/scenario_rank_sensitivity.csv`)

## 예상성과

- 선박 추가 없이 현재 편성의 출발 시각만 조정(여의도 동기화)해도 장거리 이동의 체감 통행시간을 약 18% 줄일 수 있으며, 보유 선박 안(30분 배차, 10척)에서 장거리 26%·생활권 60% 단축이 가능함을 보여 운영 개선의 우선순위를 정할 수 있음
- 2년 연속 같은 순위로 휴일 수요가 모이는 선착장(뚝섬·여의도)과 수요는 높지만 접근이 어려운 선착장(잠실·압구정)을 구분해, 유아차 동반 시범 대상과 접근 경로 개선 대상을 근거 있게 정할 수 있음
- 주말 요금 변화가 가족 이용과 부담에 미치는 영향을 사전에 추정해, 공청회와 요금 결정 과정에 이용층별 근거를 제공할 수 있음
- 평일 낮 빈 좌석과 고령층의 외출·걷기 수요를 연결하는 건강 코스를 설계해 운항 효율과 건강증진 사업의 효과를 동시에 높일 수 있으며, 공개 데이터만 쓰므로 다른 신규 교통수단의 이용 저조 진단에 그대로 재사용할 수 있음

## 분석결과 활용방안

- 운영사·미래한강본부 실무자 대시보드로 구현해 배차·동기화·급행·요금을 조정하면 이용층별 체감 통행시간, 예상 이용 변화, 필요 선박 수를 즉시 확인할 수 있음

## 부록 D. 핵심 지표 해설 — 왜 이 식인가, 무엇을 뜻하나, 얼마면 큰가

### D-1. 세 지표는 한 줄로 이어짐

```
운항 시간표 ──▶ ① 기대대기시간 / 여의도 환승대기 ──▶ ② 환승마찰지수(TFI) ──▶ ③ 수요 반응
               "얼마나 기다리나"                   "전체적으로 얼마나 힘든가"     "그래서 얼마나 더(덜) 타나"
```

- ①은 TFI를 만드는 재료이고, ③은 처방으로 TFI가 줄었을 때 그것을 이용 변화로 번역하는 단계임
- 그래서 처방(동기화·배차·급행·요금)을 넣으면 ① → ② → ③이 차례로 다시 계산되고, 대시보드 시뮬레이터도 이 순서로 동작함

### D-2. 기대대기시간

**무엇인가**: 시간표를 보지 않고 아무 때나 선착장에 도착한 승객이 다음 배까지 평균 몇 분 기다리는가.

**식이 나온 이유**: 배차가 항상 60분이면 평균 대기는 30분(배차의 절반)임. 그런데 배차가 30분, 90분으로 번갈아 있으면 평균 배차는 똑같이 60분이지만, 아무 때나 온 승객은 90분 구간에 걸릴 확률이 3배 높고 거기서 오래 기다림. 이를 반영한 것이 무작위 도착 대기 공식임[R6].

```
기대대기 = Σ(배차간격²) ÷ (2 × Σ배차간격) = (평균배차 ÷ 2) × (1 + 변동계수²)
```

- 30분·90분 예시: (30² + 90²) ÷ (2 × 120) = 37.5분 → 균일한 60분 배차(30분)보다 7.5분 더 기다림
- 뒤쪽 형태에서 `(1 + 변동계수²)`가 **불규칙성 벌점**임. 1.0이면 완전 균일, 1.1이면 불규칙성 때문에 10% 더 기다림

**판단 기준** (TCQSM 배차 서비스수준[R7]을 기대대기로 환산)

| 등급 | 배차 | 기대대기(≈배차÷2) | 의미 |
| --- | --- | --- | --- |
| A | 10분 미만 | 5분 미만 | 시간표 없이 탐. 지하철·간선버스 수준 |
| B | 10~14분 | 5~7분 | 자주 다님 |
| C | 15~20분 | 8~10분 | 기다릴 만함. 한강버스 서울시 목표(15분) |
| D | 21~30분 | 11~15분 | 시간표를 확인하기 시작함 |
| E | 31~60분 | 16~30분 | 시간표에 맞춰 일정을 짜야 함 |
| F | 60분 초과 | 30분 초과 | 선택 이용자에게 매력 없음 |

**현재 한강버스에 적용하면**

| 선착장(방향) | 평균 배차 | 균일할 때 대기 | 실제 기대대기 | 불규칙성 벌점 | 등급 |
| --- | --- | --- | --- | --- | --- |
| 마곡(여의도행) | 49분 | 24.5분 | 26분 | 1.06 | E |
| 여의도(잠실행) | 50분 | 25분 | 27분 | 1.08 | E |
| 잠실(여의도행) | 56분 | 28분 | 31분 | 1.11 | E |
| 서울숲(잠실행) | 50분 | 25분 | 27분 | 1.08 | E |
| 압구정(잠실행) | 98분 | 49분 | 53분 | 1.08 | F |
| 옥수(잠실행) | 97분 | 48.5분 | 51분 | 1.05 | F |

→ 불규칙성 벌점은 1.05~1.11로 작아, 문제는 "들쭉날쭉"보다 **배차 자체가 긴 것**임. 처방은 시간표 간격 정리보다 배차 단축 쪽이 맞음

**주의**: 배차가 길면 실제 승객은 시간표를 보고 옴. 그래도 이 값은 "시간표에 내 일정을 맞춰야 하는 불편"의 크기를 나타내므로 선착장·시나리오 간 비교 지표로는 유효함. 실제 대기시간 자체로 읽지 않음

### D-3. 여의도 환승대기

**무엇인가**: 서측 배가 여의도에 도착한 뒤, 최소 환승 3분이 지나고 처음 뜨는 동측 배까지의 시간(반대 방향도 동일).

**기준선 두 개**

| 기준선 | 값 | 의미 |
| --- | --- | --- |
| 동기화 이상값 | 약 3~5분 | 도착 3분 뒤에 연결편이 출발하도록 맞춘 상태 |
| 무조정 기대값 | 연결 노선 배차 ÷ 2 (60분 배차면 약 30분) | 두 노선이 서로 신경 쓰지 않고 운항할 때의 평균 |

- 5분 이하 → 동기화됨 / 5분~무조정값 → 부분 조정 / **무조정값 초과 → 시간표가 오히려 엇갈림**
- 현재 마곡→잠실 26분은 사실상 무조정 수준, 잠실→마곡 39분(최대 88분)은 무조정보다 나쁨 → 배를 늘리지 않고 출발시각만 바꿔 줄일 수 있는 가장 큰 누수라는 근거

### D-4. 환승마찰지수(TFI)

**무엇인가**: 배 위 시간, 기다림, 갈아타기, 걷기를 모두 "배 위에 앉아 가는 시간 몇 분과 같은 부담인가"로 바꿔 더한 체감 통행시간(분).

```
TFI = 배 위 시간 + 1.8 × (첫 대기 + 환승대기) + 10 × 환승횟수 + 도보부담(100m당 2분, 계단 100개당 4분)
```

**식이 나온 이유**: 같은 10분이라도 앉아서 가는 10분과 서서 기다리는 10분은 다르게 느껴짐. 교통공학에서는 이를 "일반화비용"으로 계산하고, 국내 연구에서 대기 1분 ≈ 차내 1.7~2.0분[R3], 환승 1회 ≈ 차내 10~15분[R4], 보행·계단 환승저항[R5]이 추정됨. TFI는 이 가중치를 한강버스 경로(지하철 → 도보 → 배 → 환승 → 배 → 도보)에 그대로 적용하고 이름만 붙인 것임.

**계산 예시 (마곡 → 잠실, 현재)**

| 구성 | 실제 시간 | 가중치 | 체감 부담 |
| --- | --- | --- | --- |
| 배 위 시간 | 133분 | ×1.0 | 133분 |
| 첫 대기 | 25분 | ×1.8 | 45분 |
| 여의도 환승대기 | 26분 | ×1.8 | 47분 |
| 환승 1회 | — | +10분 | 10분 |
| 합계(TFI) | | | **약 236분** |

**판단 기준**

| 지표 | 식 | 기준 | 현재 예시 |
| --- | --- | --- | --- |
| 마찰 비중 | (TFI − 배 위 시간) ÷ TFI | 30% 이상이면 속도보다 시간표·환승 개선 효과가 큼 | 마곡→잠실 44%, 뚝섬→잠실 84% |
| 지하철 대비 비율 | 한강버스 TFI ÷ 같은 구간 지하철 TFI | 1.0 이하 경쟁 가능 / 1.0~1.5 여가·쾌적성 수요만 / 1.5 이상 통근 대체 어려움 | 지하철 TFI는 서울교통공사 최단경로 데이터로 계산 예정 |
| 이용층 격차 | 유아차(고령층) TFI − 일반 TFI | 0분이면 무장애, 10분 이상이면 접근 개선 우선 대상, 경로 없음 = 접근 불가 | Lab 계산 예정 |

- 마찰 비중 84%인 뚝섬→잠실은 부담의 대부분이 배 밖(대기)에 있어 배차만 줄여도 크게 좋아짐(15분 배차 시 −64%). 반대로 배 위 시간이 긴 마곡→잠실은 어떤 시간표 처방으로도 −30% 안팎이 한계 → "짧은 생활권 구간은 살릴 수 있고, 장거리 통근은 어렵다"는 결론의 근거
- 위 기준값(30%, 1.0/1.5, 10분)은 선행연구 수치가 아니라 이 레시피가 정한 판단선이므로, 결과를 쓸 때 "레시피 기준"임을 밝힘

### D-5. 수요 반응

**무엇인가**: 처방으로 TFI(또는 요금)가 바뀌었을 때 이용이 몇 % 변하는가.

```
새 수요 ÷ 현재 수요 = (새 TFI ÷ 현재 TFI)^ε
```

**식이 나온 이유**: ε(탄력성)는 "비용이 1% 오르면 수요가 몇 % 변하나"임. ε = −0.5면 체감시간이 10% 늘 때 이용이 약 5% 줄어듦. 단순히 `변화율 × ε`로 곱하면 큰 변화(배차 60분 → 15분)에서 수요가 음수가 되는 등 값이 무너지므로, 어느 구간에서나 탄력성이 일정한 거듭제곱 형태를 씀. 영국 교통연구소 대중교통 수요 지침[R2]에서 쓰는 표준 형태임.

**계산 예시 (마곡 → 잠실, 여의도 동기화)**: (202 ÷ 236)^−0.5 = 1.08 → 이용 약 +8%

**ε 범위를 둔 이유**: 해외 연구값이라 서울에 그대로 맞는다는 보장이 없음. 서울은 지하철이 워낙 좋아 한강버스 개선에 대한 반응이 해외보다 작을 수 있어 보수값 −0.3을 하한으로 둠.

**판단 기준**

| 결과 | 해석 |
| --- | --- |
| ε = −0.3(보수값)에서도 +10% 이상 | 효과 확실. 우선 추진 |
| −0.5에서만 +10% 이상 | 효과 있음. 시범 후 확인 |
| 세 값 모두 ±5% 이내 | 효과 미미 |
| 부호가 음수 | 오히려 이용 감소(예: 격편 급행 단독 −1%, 뚝섬 −13%) |

- **요금에 적용할 때**: |ε| < 1이면 요금을 올려도 운임수입은 늘지만 승객은 줄어듦. 예) 주말 5,000원, ε = −0.43 → 승객 −20%, 운임수입 +34%. 그러나 한강버스는 운임이 매출의 약 4%이고 부대매출이 훨씬 커서[S3], 승객 20% 감소가 운임 증가분보다 큰 손실이 될 수 있음 → 요금 인상은 가족 1일권 같은 보완책과 함께 검토해야 한다는 근거
- **한계**: 탄력성은 작은 변화에 맞는 값이라 큰 변화에서는 오차가 커짐. 그래서 "몇 명 늘어난다"가 아니라 **처방끼리 크기를 비교**하는 데만 씀
